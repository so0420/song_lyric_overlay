서버 로그 파일의 보관에 관한 정확한 안내 (중요)

서버 로그 파일은 자정을 기준으로 일 단위 회전(rotation)하며 최대 30개까지 보관하도록 설정되어 있습니다. 그러나 로그 파일의 이름이 서버 프로세스가 시작된 시각을 기준으로 새로 만들어지기 때문에, 서버를 재시작하면 이전 실행분의 로그 파일은 자동 삭제(회전) 대상에서 제외됩니다.

그 결과 이전 실행분의 로그 파일은 운영자가 수동으로 삭제할 때까지 서버에 계속 남아 있습니다. 본 방침 작성 시점에도 한 달 이상 경과한 로그 파일이 다수 잔존하고 있음을 확인하였습니다.

따라서 서비스는 서버 로그 파일의 보관 기간을 "최대 30일"이라고 안내하지 않습니다. 정확한 사실은 "일 단위 회전이 적용되나 자동 삭제가 완전하게 이루어지지 않으며, 운영자가 수동으로 정리할 때까지 보관된다"는 것입니다. 서비스는 이를 개선하기 위한 조치를 검토하고 있으며, 개선이 완료되면 본 방침을 변경하여 공지하겠습니다.

2. 가사의 공개 범위에 관한 고지 (중요)

  • 이용자가 가사를 저장하면 해당 가사는 저장 시점에 자동으로 '전체공개(public)' 상태로 고정됩니다.
  • 일반 이용자는 가사의 공개 범위를 지정하거나 변경할 수 없습니다. 공개 범위(전체공개/비공개/허용목록)의 설정·변경 권한은 관리자에게만 있습니다.
  • 전체공개된 가사는 서비스의 가사 목록에서 다른 이용자에게 노출되고, 다른 이용자의 노래하기·OBS 자막에서 사용될 수 있으며, 같은 곡을 노래책에 보유한 다른 스트리머의 항목에 자동으로 연결될 수 있습니다(가사 편집기의 '노래책 자동 연결' 기능을 끄면 자동 연결은 발생하지 않으나, 공개 자체가 취소되지는 않습니다).
  • 공개를 원하지 않으시는 경우, 가사를 저장하지 않으시거나 저장한 가사를 삭제하시고, 필요 시 제20조의 연락처로 비공개 전환 또는 완전 삭제를 요청해 주시기 바랍니다.
  • 가사 삭제는 소프트 삭제 방식입니다. 삭제하시면 서비스 화면에서 즉시 노출이 중단되지만, 데이터베이스에는 삭제 표시만 기록되고 본문은 남습니다.

  • OBS 가사 자막 화면에는 신청자 정보가 포함되지 않습니다.
  • 신청자 닉네임은 해당 노래책을 운영하는 스트리머 본인의 관리 화면(노래책 관리 페이지, 노래하기 화면의 알림) 에서만 확인할 수 있습니다.

  4. 자동화된 결정에 대한 거부 또는 설명 요구는 제20조의 연락처로 하실 수 있습니다.

제16조 (개인정보의 추가적인 이용·제공에 관한 판단기준)

「개인정보 보호법」 제15조 제3항 및 제17조 제4항, 같은 법 시행령 제14조의2에 따른 개인정보의 추가적인 이용·제공은 현재 이루어지고 있지 않습니다(해당 없음).

서비스는 제1조에 기재한 수집·이용 목적의 범위를 벗어나는 추가적인 이용·제공을 하지 않습니다. 향후 추가적인 이용·제공이 필요하게 되는 경우에는 다음 사항을 모두 고려하여 판단하고, 그 판단기준과 내용을 본 개인정보 처리방침에 미리 공개한 후에 처리하겠습니다.

  1. 당초 수집 목적과 관련성이 있는지 여부
  2. 개인정보를 수집한 정황 또는 처리 관행에 비추어 볼 때 추가적인 이용·제공에 대한 예측 가능성이 있는지 여부
  3. 정보주체의 이익을 부당하게 침해하는지 여부
  4. 가명처리 또는 암호화 등 안전성 확보에 필요한 조치를 하였는지 여부

제17조 (개인정보의 안전성 확보조치에 관한 사항)

서비스는 「개인정보 보호법」 제29조 및 같은 법 시행령 제30조에 따라 다음과 같은 안전성 확보조치를 하고 있습니다. 아래는 실제로 적용되어 있는 조치만을 기재한 것이며, 적용되지 않은 사항은 제3항에 그대로 밝혔습니다.

1. 기술적 조치

구분적용 내용
비밀번호의 일방향 암호화회원의 비밀번호는 bcrypt 알고리즘으로 해시 처리하여 저장하며, 평문으로 저장하거나 복호화할 수 있는 형태로 보관하지 않습니다
인증 코드의 보호이메일 인증·이메일 변경·비밀번호 재설정 코드(OTP)는 SHA-256 해시 형태로만 저장하고, 10분의 유효시간과 5회의 시도 횟수 제한을 적용합니다
접속 토큰의 최소화실시간 동기화(WebSocket) 접속 토큰은 60초 유효한 1회용(43자 난수)으로 발급하고 사용 즉시 폐기합니다. OBS 오버레이 토큰은 이용자 식별정보를 포함하지 않는 43자 난수 문자열이며, 이용자가 오버레이 설정 페이지에서 언제든 재발급하여 기존 토큰을 무효화할 수 있습니다. 비활성 계정의 오버레이 토큰은 검증 단계에서 차단됩니다
외부 인증 토큰의 미보관소셜 로그인 제공자(Google·네이버) 및 치지직의 접근 토큰(액세스·리프레시 토큰)을 저장하지 않습니다
세션 보호로그인 세션 쿠키에 전자서명을 적용하여 위·변조를 방지하고, HttpOnly 및 SameSite=Lax 속성을 설정하여 스크립트 접근과 교차 사이트 전송을 제한합니다
요청 위조(CSRF) 방지가사, 노래책·수록곡, 신청곡, 오버레이 설정·프리셋·토큰 재발급, 곡 등록, 타임라인, 치지직 연동 해제, 관리자 사용자 전환 등 주요 상태 변경 요청에 대해 CSRF 토큰 및 요청 출처(Origin) 검증을 적용합니다 (적용되지 않은 범위는 제3항 참조)
관리자 권한의 실시간 검증관리자 권한은 세션 값이 아니라 매 요청마다 데이터베이스에서 재확인하므로, 권한이 회수되면 즉시 반영됩니다
브라우저 보안 헤더 적용콘텐츠 보안 정책(CSP), X-Content-Type-Options, X-Frame-Options, X-XSS-Protection, Referrer-Policy를 적용하고, Permissions-Policy를 통해 위치정보·카메라·마이크·결제 API 접근을 차단합니다
비정상 접근 제어로그인·회원가입·인증코드 발급·검색·노래 신청 등 주요 요청에 대해 요청 속도 제한(Rate Limit)을 적용합니다
통신 구간 암호화서비스는 HTTPS를 통해 제공되며, 이메일 발송은 STARTTLS로 암호화된 SMTP 통신을 사용합니다
내부 시스템의 외부 노출 차단데이터베이스, 캐시 서버, 검색엔진은 서비스 서버 내부에서만 접근 가능하도록 운영합니다
불필요한 정보의 미수집곡 등록 시 업로드된 이미지 파일은 저장하지 않고 폐기하며, 이용자의 브라우저 User-Agent를 읽거나 저장하지 않습니다 (가사 재생용으로 직접 업로드한 음원 파일은 아래 행의 통제 아래 저장됩니다)
업로드 파일의 접근 통제업로드된 음원 파일은 웹에서 직접 접근할 수 있는 정적 경로가 아닌 별도 디렉터리에 임의로 생성한 이름으로 저장되며, 파일 주소를 아는 것만으로는 접근할 수 없습니다. 재생 요청 시 서버가 연결된 가사의 열람 권한을 매번 확인한 뒤 로그인한 이용자에게만 전송합니다. 업로드 시에는 파일의 실제 형식을 내용(매직바이트)으로 검사하여 음성 파일이 아닌 것을 거부하고, 크기(50MB)를 제한하며, 업로드 횟수에 속도 제한을 적용합니다

2. 관리적 조치

구분적용 내용
개인정보 취급자의 최소화개인정보에 접근할 수 있는 권한은 관리자 권한을 가진 계정으로 한정합니다
접근기록의 보관관리자의 주요 행위(사용 승인·거절·회수, 사용자 전환 등)를 수행자·수행 내용·대상·요청 IP 주소와 함께 기록합니다
관리자의 '사용자 전환' 기능에 대한 고지서비스에는 장애 대응 및 기능 확인을 위해 관리자가 특정 이용자 계정 상태로 전환하여 해당 이용자의 화면과 데이터를 확인할 수 있는 기능이 있습니다. 이 기능의 사용 사실은 대상 이용자의 이메일·이름 및 수행 관리자의 IP 주소와 함께 접근기록에 남으며, 전환 상태임을 알리는 안내가 화면에 표시됩니다

3. 현재 적용되지 않은 사항에 대한 안내

정확한 고지를 위해 다음 사항을 함께 알려드립니다. 서비스는 아래 사항의 개선을 검토하고 있습니다.

  • 비밀번호를 제외한 개인정보(이메일 주소, 이름, IP 주소 등)는 데이터베이스에 암호화되지 않은 형태로 저장됩니다.
  • 서버 로그 파일에는 이메일 주소, 시청자 닉네임, 채팅·후원 문구가 평문으로 기록되며, 자동 삭제가 완전하게 이루어지지 않습니다(제2조 제1항 참조).
  • 다음 요청에는 별도의 CSRF 토큰 검증이 적용되어 있지 않고 세션 쿠키의 SameSite 속성에만 의존합니다 — 회원가입·이메일 인증·로그인·로그아웃·비밀번호 찾기 및 재설정, 회원정보(이름·이메일) 수정, 비밀번호 변경, 이메일 변경 인증코드 발송, 소셜 계정 연결 해제, 회원 탈퇴, 오버레이 사용 요청 제출, 관리자 승인/거절/권한 회수 및 자동 승인 설정.
  • 로그인 세션 쿠키에 Secure 속성이 설정되어 있지 않습니다.
  • 가사 삭제는 물리적 삭제가 아닌 소프트 삭제로 처리됩니다. 회원 탈퇴는 비활성화 후 30일이 지나면 계정 식별정보가 자동 파기됩니다(제8조).
  • 관리자 접근기록, 오버레이 사용 요청 이력 등에 대한 자동 파기 절차가 없습니다.
  • 업로드된 음원 파일은 서버 디스크에 암호화되지 않은 형태로 저장됩니다.
